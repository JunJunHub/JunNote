#### 3.2.2 并发模式

**Worker Pool模式**
```go
func workerPool(tasks <-chan Task, results chan<- Result) {
    for task := range tasks {
        results <- process(task)
    }
}

func main() {
    tasks := make(chan Task, 100)
    results := make(chan Result, 100)

    // 启动worker
    for i := 0; i < 10; i++ {
        go workerPool(tasks, results)
    }
}
```

### 3.4 音视频协议核心知识点

#### 3.4.1 音视频基础

**视频编码标准**
| 标准 | 特点 | 应用场景 |
|-----|------|---------|
| **H.264/AVC** | 成熟、兼容性好 | 监控、直播、点播 |
| **H.265/HEVC** | 压缩率更高（提升50%） | 4K/8K高清视频 |
| **MJPEG** | 帧内压缩、编辑友好 | 监控抓拍 |

**音频编码标准**
| 标准 | 特点 | 应用场景 |
|-----|------|---------|
| **AAC** | 高质量、高压缩 | 流媒体、移动端 |
| **G.711** | 无压缩、简单 | 传统电话、PBX |
| **G.726** | ADPCM压缩 | VOIP、监控 |

#### 3.4.2 封装格式

**常见容器格式**
| 格式 | 特点 | 应用 |
|-----|------|------|
| **MP4** | 兼容性好 | 点播、存储 |
| **FLV** | 适合流式传输 | 直播 |
| **TS** | 适合传输、纠错 | DVB、IPTV |
| **MKV** | 开源、灵活 | 存储 |

#### 3.4.3 流媒体协议

**RTSP（Real Time Streaming Protocol）**
```
特点：
- 基于TCP/UDP的应用层协议
- 控制信令与数据传输分离
- 支持实时播放、暂停、快进

工作流程：
1. DESCRIBE: 获取媒体描述
2. SETUP: 建立传输会话
3. PLAY: 开始播放
4. PAUSE/TEARDOWN: 暂停/停止
```

**RTMP（Real Time Messaging Protocol）**
```
特点：
- 基于TCP
- 低延迟（1-3秒）
- Flash直播标准

应用场景：
- 直播推流
- 实时通讯
```

**HLS（HTTP Live Streaming）**
```
特点：
- 基于HTTP
- 切片传输（.ts文件 + .m3u8索引）
- 延迟较高（10-30秒）
- 原生支持iOS/Android

工作原理：
1. 视频切片成.ts文件
2. 生成.m3u8播放列表
3. 客户端按顺序下载播放
```

**WebRTC**
```
特点：
- 浏览器原生支持
- 超低延迟（<100ms）
- 支持P2P直连

核心技术：
- ICE/STUN/TURN: NAT穿透
- SRTP: 安全传输
- 反馈机制: 动态调整码率
```

#### 3.4.4 SIP协议

**SIP（Session Initiation Protocol）**
```
应用：
- VOIP电话
- 视频会议
- GB28181国标协议基础

核心方法：
- INVITE: 建立会话
- ACK: 确认应答
- BYE: 结束会话
- REGISTER: 注册
- MESSAGE: 即时消息
```

**SDP（Session Description Protocol）**
```
作用：
- 描述媒体会话信息
- 包含编解码、传输地址等

示例：
v=0
o=- 123456 2 IN IP4 192.168.1.100
s=-
c=IN IP4 192.168.1.100
t=0 0
m=video 6000 RTP/AVP 96
a=rtpmap:96 H264/90000
```

#### 3.4.5 GB28181协议

**GB28181（公共安全视频监控联网系统）**
```
特点：
- 中国国家标准
- 基于SIP协议
- 用于安防监控领域

核心功能：
1. 设备注册与认证
2. 目录查询
3. 实时视频预览
4. 历史视频回放
5. 云台控制
6. 报警订阅

消息流程：
注册 -> 目录查询 -> 邀请视频 -> 建立RTP传输
```

**实战实现要点**
- SIP信令：使用oSIP或自研协议栈
- RTP传输：PS封装（H.264+G.711）
- 心跳保活：Keep-Alive机制
- 级联支持：多级平台互联

#### 3.4.6 其他常用协议

```
特点：

核心功能：
```

```
libavutil: 工具库
libswscale: 图像缩放与转换
libswresample: 音频重采样
```

**常用命令**
```bash
# 推流
ffmpeg -re -i input.mp4 -c copy -f rtsp rtsp://server/live

# 拉流保存
ffmpeg -i rtsp://server/live -c copy output.mp4

# 转码
ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4

# 提取视频
ffmpeg -i input.mp4 -an -c:v copy output.h264

# 截图
ffmpeg -i input.mp4 -ss 00:00:05 -vframes 1 output.jpg
```

**代码示例**
```c
// FFmpeg API使用
AVFormatContext *fmt_ctx = NULL;
AVCodecContext *codec_ctx = NULL;

// 打开输入
avformat_open_input(&fmt_ctx, url, NULL, NULL);

// 查找流信息
avformat_find_stream_info(fmt_ctx, NULL);

// 查找解码器
codec = avcodec_find_decoder(AV_CODEC_ID_H264);

// 打开解码器
avcodec_open2(codec_ctx, codec, NULL);

// 读取帧
av_read_frame(fmt_ctx, &packet);

// 解码
avcodec_send_packet(codec_ctx, &packet);
avcodec_receive_frame(codec_ctx, &frame);
```

**Q7: Go的Goroutine为什么比线程更轻量**

| 对比项 | 线程 | Goroutine |
|-------|------|-----------|
| **栈大小** | 1MB起（固定） | 2KB起（动态扩展） |
| **创建成本** | 高（系统调用） | 低（用户态） |
| **调度** | OS内核调度 | Go runtime调度 |
| **切换成本** | 高（内核态切换） | 低（用户态切换） |
| **数量级** | 几千个 | 百万级 |

**Go调度器（GMP模型）：**
- **G（Goroutine）**: 协程实例
- **M（Machine）**: 系统线程
- **P（Processor）**: 调度器，维护G的队列

**Q11: 如何解决音视频不同步问题**

**原因分析：**
1. 音视频采集时间不同
2. 编解码时间不同
3. 网络传输延迟不同
4. 播放缓冲不一致

**解决方案：**
1. **统一时间戳**：使用统一的时钟源
2. **缓冲策略**：音视频独立缓冲，动态调整
3. **丢帧处理**：视频丢帧追赶，音频不丢
4. **平滑处理**：调整播放速度微调

---

**Q12: FFmpeg中av_read_frame和avcodec_send_packet的区别**

```
av_read_frame:
- 从封装格式中读取一个AVPacket
- 包含编码后的数据
- 可能是音频也可能是视频

avcodec_send_packet:
- 将AVPacket发送给解码器
- 送入解码队列
- 返回EAGAIN表示需要接收更多frame

avcodec_receive_frame:
- 从解码器接收解码后的AVFrame
- 包含原始像素/采样数据
- 可能需要多次调用才能获得一帧
```
